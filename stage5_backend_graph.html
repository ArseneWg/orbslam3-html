  1. SetAcceptKeyFrames(false)
  2. CheckNewKeyFrames()

2. LocalInertialBA 的窗口怎么选

源码以当前 KF 开始，沿 mPrevKF 向后取时间窗口：通常最多 10 个；bLarge 时最多 25 个。窗口最老 KF 的前一帧被放入 fixed KFs 作为锚点。

源码直接可见Optimizer.cc L2383–2442
maxOpt = 10;
if(bLarge) maxOpt = 25;

vpOptimizableKFs.push_back(pKF);
for(...) {
  if(vpOptimizableKFs.back()->mPrevKF)
    vpOptimizableKFs.push_back(...mPrevKF);
}

lFixedKeyFrames.push_back(
  vpOptimizableKFs.back()->mPrevKF

3. LocalMapping 还会主动判断“运动是否足够”

IMU 已初始化但还没完成第二阶段惯性 BA 时，源码计算最近两段相机中心移动距离；如果初始化累计时间 <10s 且移动 <0.02m，会标记 bad IMU 并请求 reset active map。

LocalMapping.cc motion gate
这不是“IMU 数值坏了”的唯一含义；源码中的 mbBadImu 也承担“运动激励不足导致惯性估计不可信”的控制作用。

6. Inertial loop 的姿态一致性检查

确认 Loop 后，如果 Map 是 inertial，源码将回环修正转换为旋转向量 phi。只有：

|phi.x| < 0.008
|phi.y| < 0.008
|phi.z| < 0.349

才认为是 good loop；否则打印 BAD LOOP!!!。若已经完成 InertialBA2，源码把旋转向量 phi 的 x/y 分量清零、只保留 z 分量；源码注释称其为 “force only yaw”，但 phi 本身是 SO(3) 对数映射向量，不是 Euler 角。

LoopClosing.cc inertial loop gate

7. CorrectLoop() 实际修改什么

  1. RequestStop LocalMapping，并清队列。
  2. 如果 Global BA 正在运行，先终止。
  3. 取得当前 KF 的共视邻居，传播 corrected Sim3。
  4. 把 corrected Sim3 转回 SE3 更新 KF pose。
  5. MapPoint：先用旧 Sim3 映射，再用 corrected inverse 映回世界坐标。
  6. 若 IMU 已初始化，按旋转校正 KeyFrame velocity。
  7. 更新连接关系，并将当前侧和 loop 侧重复 MapPoint Replace/Fuse。
LoopClosing.cc CorrectLoop

8. Atlas：为什么系统能“丢了以后另起一张图”

Atlas::CreateNewMap() 会把旧 current map 标记为 stored，再创建新的 Map(mnLastInitKFidMap) 并设为 current。这就是 Tracking 丢失后可以新建子地图、以后再 Merge 的数据结构基础。
