入口精读：IMU 怎样被切成“帧间数据包”

这一页不讲泛泛的“传感器融合”，只沿 EuRoC 单目惯性例子的真实 for/while 循环解释数据怎么进入系统。

阶段一概览源码精读首页

源码真实输入形状

EuRoC 例子先分别读取图像、IMU，然后在处理每张图像前，把所有 t_imu <= t_camera 的 IMU 样本压入 vImuMeas，最终一次性传给 TrackMonocular。

源码直接可见

图像是主节拍

例子循环以图像索引 ni 前进；IMU 通过 while 条件追到当前图像时间戳。

由源码行为推导

这不是硬件同步器

代码行为表明核心 API 接受“一帧图像 + 一段 IMU 序列”，所以时间同步策略在输入层就很重要。

调用链

LoadImages→LoadIMU→vImuMeas→TrackMonocular

后面的 System 不再关心“数据来自 CSV 还是实时驱动”，它只看到统一后的输入。

first_imu 是游标

它不会每帧从 IMU 数组头部重新扫描，而是持续前进；因此每个 IMU 样本只会被消费一次。

源码直接可见

vImuMeas 的边界由当前相机时间戳决定

while 条件直接使用当前图像时间戳；这决定了进入 TrackMonocular 的 IMU 时间窗。

源码直接可见

TrackMonocular 每帧只调用一次

例子在每张图像的循环中调用一次核心接口。

由源码行为推导

接入实时设备时应保留同样的数据契约

实时驱动可不同，但最好仍把“截至当前图像时间”的 IMU 包组装成同类向量。
