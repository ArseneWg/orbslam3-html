这一页讲什么？

从 Examples/Monocular-Inertial/mono_inertial_*.cc 的例子程序开始，回答三个问题：

  • 图像和 IMU 是如何从数据集文件读进来的？
  • 为什么 IMU 不是“一次一条地立即计算”，而是要按图像帧切片打包？
  • 最终传入核心系统的数据结构是什么？

输入形式

单目 + IMU 的典型输入不是“同步对齐的一张图 + 一条 IMU”，而是：

图像帧 k      : I_k, timestamp t_k
图像帧 k+1    : I_{k+1}, timestamp t_{k+1}
IMU 序列      : 从 first_imu 游标起，取所有尚未消费且 t_i <= t_{k+1} 的样本
系统调用      : TrackMonocular(I_{k+1}, t_{k+1}, vImuMeas)

入口流程图

为什么要按图像帧切片收集 IMU？

ORB-SLAM3 的前端仍以图像帧为“主事件”。每来一张图，系统都会建立一个 Frame 并更新当前位姿。IMU 的角色是帮助系统在相邻图像之间做更合理的运动预测与后端约束。所以例子程序的自然工作方式是：每处理一张图，就从持续前进的 IMU 游标中收集“尚未消费且时间戳不晚于当前图像”的样本；EuRoC 示例在开始时还特意保留一个不晚于首帧的边界样本，供后续预积分处理时间边界。

这也是你以后接实时传感器时最该模仿的接口行为：图像是主时钟，IMU 是帧间补偿与优化约束。

你在这里能观察到的源码事实

  • 例子程序负责数据集 I/O，而不是 System 或 Tracking 去自己读文件。
  • 传入系统的 IMU 结构是一个向量，不是单个采样点。
  • 真正对外暴露的前端入口是 TrackMonocular()，所以你自己做数据接入时也应模仿这个形状。
  • 单目惯性模式下，Sensor 枚举值是 IMU_MONOCULAR，在构造 System 时就已确定。

源码锚点

  • Examples/Monocular-Inertial/mono_inertial_euroc.cc：典型 EuRoC 单目惯性例子。
  • Examples/Monocular-Inertial/mono_inertial_tum_vi.cc：典型 TUM-VI 单目惯性例子。
  • 你重点要关注：加载时间戳、收集当前图像前的 IMU 段、然后调用 SLAM.TrackMonocular(..., vImuMeas) 的那一段循环。
