从对象关系读懂系统

很多人读 ORB-SLAM3 卡住，不是因为公式太难，而是因为对象太多。你只要先掌握下面几个类的角色，代码会清晰很多。

Frame KeyFrame MapPoint Map / Atlas KeyFrameDatabase ORBVocabulary

对象关系一句话版

  • Frame：当前临时观测容器。
  • KeyFrame：被长期保留并参与建图/闭环的 Frame。
  • MapPoint：被多个关键帧观测到的 3D 点。
  • Map：一张地图中的关键帧与地图点集合。
  • Atlas：多张 Map 的管理器。
  • KeyFrameDatabase：做 BoW 检索的数据库。
  • ORBVocabulary：BoW 词典。

对象关系表

对象存什么谁创建 / 谁主要使用生命周期
Frame当前图像的关键点、描述子、位姿、与地图点的当前关联Tracking 构造并使用短：按帧存在
KeyFrame长期保留的关键帧、BoW、共视关系、观测关系Tracking 创建，LocalMapping/LoopClosing 长期使用长：直到被裁剪
MapPoint3D 位置、描述子、法向、可见性统计、被哪些关键帧观测初始化/局部建图创建，全系统共享长：直到被判坏点
Map / Atlas地图集合、活动地图、关键帧与地图点组织System 创建，全系统共享贯穿全局
KeyFrameDatabase基于 BoW 的关键帧倒排索引/检索结构System 创建，Tracking/LoopClosing 使用贯穿全局
ORBVocabularyBoW 词典System 加载，Frame/KeyFrame/Database 使用贯穿全局

Frame 与 KeyFrame 的差异

不要把它们混成一个概念。Frame 是前端的连续时间载体；KeyFrame 是后端的离散图节点。所有 KeyFrame 都是由某个 Frame 升级而来，但不是每个 Frame 都能变成 KeyFrame。

MapPoint 的本质

不是“点云里随便一个点”，而是带有多帧观测关系、可见性统计与代表性描述子的图结构节点。

Atlas 的意义

Atlas 让 ORB-SLAM3 能管理多张地图，这也是它支持地图合并和更复杂长期运行行为的基础。

对象之间如何相互引用？

  • Frame 会临时关联一些 MapPoint。
  • KeyFrame 长期持有对其观测到的 MapPoint 的引用。
  • MapPoint 反过来记录自己被哪些 KeyFrame 观测到。
  • Map 持有 KeyFrame 和 MapPoint 容器。
  • Atlas 管理一个或多个 Map，并维护 active map。

建议的源码阅读顺序

  1. 先看 Frame.h/.cc：当前帧里有哪些成员。
  2. 再看 KeyFrame.h/.cc：哪些成员被“长期化”了。
  3. 再看 MapPoint.h/.cc：3D 点如何维护观测关系。
  4. 最后看 Map.h/.cc 与 Atlas.h/.cc：地图层级如何组织。
