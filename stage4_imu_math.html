IMU 不是“额外传感器”：它改变了系统状态空间

从源码看，ORB-SLAM3 不只是给视觉位姿加一个预测。初始化完成后，系统显式维护旋转、位置、速度、陀螺偏置、加速度偏置、重力方向与尺度。

GrabImuData→PreintegrateIMU→PredictStateIMU→InitializeIMU→InertialOptimization→FullInertialBA

1. PreintegrateIMU：帧间样本怎样压缩

源码先从 mlQueueImuData 取出上一帧到当前帧之间的采样，并针对区间首尾做时间边界补偿；中间样本使用相邻两次测量的平均值。

源码直接可见Tracking.cc L1624–1734
acc = (imu[i].a + imu[i+1].a) * 0.5f;
angVel = (imu[i].w + imu[i+1].w) * 0.5f;
tstep = imu[i+1].t - imu[i].t;

mpImuPreintegratedFromLastKF->IntegrateNewMeasurement(acc,angVel,tstep);
pImuPreintegratedFromLastFrame->IntegrateNewMeasurement(acc,angVel,tstep);
由源码行为推导

为什么同时有 FromLastKF 和 FromLastFrame？

同一批高频 IMU 测量被累计到两个时间基准：一个用于当前帧相对上一帧的短时预测；另一个持续从上一关键帧累计，为关键帧级惯性约束准备数据。

2. PredictStateIMU：源码中的状态传播

代码明确使用重力 Gz=(0,0,-g) 和预积分得到的 ΔR / Δp / Δv：

R₂ = Normalize( R₁ · ΔR(bias) )
p₂ = p₁ + v₁Δt + ½GΔt² + R₁Δp(bias)
v₂ = v₁ + GΔt + R₁Δv(bias)
Tracking.cc PredictStateIMU
当 mbMapUpdated 为 true 时，预测从 LastKeyFrame 状态开始；否则从 LastFrame 开始。这是源码里非常重要的“后端更新后重新锚定预测”的分支。

5. InitializeIMU 如何估计重力初值

源码按 mPrevKF 链取出时间序列关键帧；对有预积分的 KF 累计：

dirG -= R_prev · Δv_preintegrated

然后归一化 dirG，计算理想重力轴 gI=(0,0,-1) 到该方向的旋转 Rwg。同时用相邻 IMU 位置差除以预积分时间给关键帧设置速度初值。
