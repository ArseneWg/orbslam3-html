System 启动：总入口如何装配整套 SLAM

System 是“装配工厂”

System 并不直接完成所有算法，而是把词袋、地图、关键帧数据库、Tracker、LocalMapping、LoopClosing、Viewer 等对象组合起来。你可以把它理解成整个 SLAM 程序的“总配电箱”。

  • 加载 ORB 词袋（BoW 所需）。
  • 读取设置文件，初始化相机与参数。
  • 创建 Atlas 与 KeyFrameDatabase。
  • 创建 Tracking / LocalMapping / LoopClosing / Viewer。
  • 拉起后台线程，并在成员之间互相注入指针。

外部最关键的接口

System(const string &voc, const string &settings,
       eSensor sensor, bool bUseViewer = true, ...)

Sophus::SE3f TrackMonocular(const cv::Mat &im,
       const double &timestamp,
       const vector<IMU::Point>& vImuMeas = {},
       string filename = "");

这两个接口已经足够说明：系统先在构造期固定传感器模式，再在运行期逐帧喂数据。

System::TrackMonocular 做了什么？

  1. 处理模式切换与复位请求（例如只定位模式 / SLAM 模式、重置地图）。
  2. 如果当前模式带 IMU，则把 vImuMeas 中的每个 IMU 样本交给 mpTracker->GrabImuData()。
  3. 调用 mpTracker->GrabImageMonocular() 真正执行当前帧跟踪。
  4. 把 Tracking 的状态、当前跟踪到的地图点与关键点缓存到 System 层，供外部查询。
这一步说明一个很重要的设计：System 本身尽量薄。它主要做线程与模块管理，而把视觉/惯性细节留给 Tracking 和后端线程。

模块连接关系

  • Tracking 持有对 Atlas、KeyFrameDatabase、LocalMapping、LoopClosing、Viewer 的访问或回调连接。
  • LocalMapping 与 LoopClosing 也需要访问 Atlas / Tracker / Database，才能共享地图对象与图优化结果。
  • 这种“互相知道彼此”的结构会让源码看起来耦合较重，但它换来了运行时跨线程协作的便利。

作为读码者，你此处应该抓住什么？

  • Sensor 模式在构造时就固定，不是在 Tracking 内部临时猜测。
  • TrackMonocular 是你顺藤摸瓜去 GrabImageMonocular 的桥。
  • System 层缓存 Tracking 状态，因此外部程序不需要深入 Tracker 也能取到最近位姿与跟踪状态。

源码锚点

  • include/System.h：构造函数、TrackMonocular()、模式切换、重置与轨迹保存接口。
  • src/System.cc：系统对象装配、线程创建、IMU 数据转交 GrabImuData()、调用 GrabImageMonocular()。
